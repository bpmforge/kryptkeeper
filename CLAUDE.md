# Kryptkeeper — the laws

Self-hosted machine-identity / certificate-lifecycle platform. Go backend
(`cmd/`, `internal/`), React+Vite+TypeScript frontend (`ui/`), Postgres.
Module name is `kryptkeeper`, Go 1.26.

Short and mandatory.

## Non-negotiable

- **This is a PKI product. Cryptographic behaviour is never "made to pass".**
  If a test fails because a signature, chain, expiry or key-usage check is
  correct and the test's expectation is wrong, fix the test. Never loosen a
  verification path to make a gate green. If a ticket appears to require
  weakening one, stop and write a `HANDOFF:` note.
- **Private key material never leaves its boundary.** No key bytes in logs,
  errors, API responses, test fixtures committed as real keys, or the board.
  Test keys are generated in-test or clearly-marked fakes.
- **Proposer ≠ approver.** The MCP server's writes are proposal-only behind a
  human approval queue, and that separation is enforced, not documented. Test
  doubles must preserve it.
- **Multi-tenancy is flag-gated.** A change that leaks across a tenant
  boundary is a security defect, not a bug.
- **Audit records are append-only.** Anything you cannot reconstruct from the
  audit log is a bug.

## Code conventions (from CONTRIBUTING.md — these are already the house style)

- **Feature-sliced package layout, not layered.** Follow the existing shape of
  `internal/`; do not introduce `service/`, `repository/`, `util/` strata.
- **No new global state.** Inject dependencies through constructor arguments.
- **Comments explain _why_, never _what_** — hidden constraints, workarounds,
  spec references. Delete narration.
- **Every new package has at least one `_test.go`.** Aim >80% coverage on new
  packages.
- **Build-tag-guarded files** (`//go:build windows`, `//go:build pkcs11`) must
  ship a corresponding default-build stub.
- **Atomic commits**, one logical change each. Stage explicit paths — never
  `git add -A`.

## The gate — what "green" actually means here

```bash
go build ./...          # must pass
go test ./...           # must pass (36 packages ok as of 2026-09-10)
```

For tickets touching `ui/`:

```bash
cd ui && npm run lint && npm test -- --run
```

Heavier suites, used by CI and available to you:

```bash
bash scripts/test/run.sh --suite protocol --suite integration
bash scripts/test/run.sh --suite smoke
make test-race          # race detector
```

## Migration version numbers

Versions are **gap-tolerant, not contiguity-strict**. Migration numbers are
claimed up front, but changes land out of numeric
order, so a gap between versions is expected and not an error. A **duplicate**
version is different: `internal/db/migrate.go`'s `loadMigrations` keys
migrations by `map[int]migrationFile` and applies them in sorted numeric
order — a gap is provably harmless to that runner, but a duplicate silently
overwrites one migration's `schema_migrations` row with another's, corrupting
the schema. So:

- `tests/protocol/run.sh` only rejects a duplicate version; it does not check
  for contiguity.

When starting a change, pick the next free version at that time; you do not
need to renumber later work just because an earlier-numbered migration lands
first.

## API-contract trap

`ui/` generates its TypeScript types from `docs/openapi.yaml`
(`npm run gen:api-types`, wired as `prebuild` and `pretest`). **A backend
response-shape change is not done until `docs/openapi.yaml` is updated** — the
frontend will otherwise compile against a stale contract, and the drift is
invisible until runtime. This has bitten the project before (see
`docs/LESSONS.md`).

> **If you edit `docs/openapi.yaml`, COMMIT the regenerated
> `ui/src/generated/api-types.ts` — do not revert it.** That file is tracked
> *and* regenerated by `pretest`/`prebuild`, so trying to leave it untouched is
> a trap with no exit: every `npm --prefix ui test` run in the gate rewrites it,
> and reverting it just re-dirties the tree on the next invocation. The
> artifact must follow its source; a tracked generated file that lags its spec
> is the same contract drift this section exists to prevent.

## Verify before writing

For any external Go module or npm package API you are about to call, confirm
the real signature — `go doc <pkg> <symbol>`, the module source under
`$(go env GOMODCACHE)`, or Context7 for JS. Never write an API from memory.
Crypto and PKI libraries (`crypto/x509`, ACME clients, PKCS#11 bindings,
Vault's API) are especially easy to hallucinate, and a plausible-looking wrong
call in this codebase is a security bug rather than a compile error.

## Authority

Agents working in this repo never merge to `main`, never push, and never delete

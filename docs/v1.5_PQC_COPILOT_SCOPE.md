# Kryptkeeper v1.5 — PQC Migration Copilot (Scope)

**Date:** 2026-06-17
**Plan reference:** `docs/archive/GO_FORWARD_PLAN.md` §4 Moat 2
**Status:** SHIPPED — v1.5.0 (tagged; see CHANGELOG.md). This doc is the original scoping record; per-item statuses below are historical. _(Re-statused 2026-07-15, design review G-7.)_

## 1. The thesis

> We already issue ML-DSA and hybrid certs — table stakes by 2028. The product
> nobody has is the **journey**: a CISO can't buy "PQC support," they need a
> plan with dates and proof of progress.

v1.5 turns "we support PQC" into a tracked migration program: classify exposure,
plan waves, execute hybrid rollout, and **prove progress against the 2030/2031
deadlines** — trending over time.

## 2. What already exists (code-verified 2026-06-17)

- **Planner**: `internal/pqc/planner.go` — `Planner.GenerateRoadmap(certs)` →
  `MigrationRoadmap` with prioritized `MigrationItem`s (CA = critical;
  long-lived classical = high / HNDL; manual = medium; short auto-renewable =
  low). **Solid, but unwired** — referenced only in a test. No handler, no UI.
- **PQC issuance**: ML-DSA + hybrid certs already issue
  (`internal/keystore/{mldsa,hybrid}.go`, `internal/ca/{mldsa,hybrid}_cert.go`).
  "Execute" has a transport.
- **Per-cert classification**: `CertificateItem.PQCReadiness`
  (not_applicable / vulnerable / migration_ready / quantum_safe / hybrid).
- **Trend foundation**: posture snapshots already persist `pqc_score_percent`
  daily (`posture_snapshots`, v1.2) — the "proof of progress over time" data
  already accrues.
- **Deadline logic**: the Algorithm Sunset report + `OUTLIVES_NIST_SUNSET` risk
  signal already encode NIST 800-131A 2030/2031 dates.
- **PDF packs**: v1.4's `fpdf` renderer can produce a PQC migration report.

What's missing: wiring the planner to an API/UI, HNDL-signal enrichment,
migration **waves** (tracked sets with owners/deadlines), and a **countdown +
proof** report.

## 3. The four pillars (from Moat 2)

### Classify — HNDL exposure
The planner classifies by validity + CA + auto-renewable. Enrich `classifyCert`
with harvest-now-decrypt-later signals already in the inventory:
- code-signing EKU (long-lived trust anchor) → elevate priority,
- long-lived TLS on sensitive paths (owner team / labels like `pci`, `prod`),
- large SAN sprawl (broad exposure).
Output: a per-cert HNDL score + reason, feeding the roadmap.

### Plan — migration waves
Group vulnerable certs into ordered **waves** (test → internal →
customer-facing), each a tracked set with an owner and a target date. Derive a
default wave from existing signals (ownership team, labels, public-vs-internal
by SAN/CN) with manual override. DB-backed so waves are editable and persist.

### Execute — hybrid rollout per wave
Track per-cert migration status within a wave (pending → migrating → migrated),
updated when a cert's `PQCReadiness` flips to migration_ready/quantum_safe at
renewal. (Re-issue-now action is a stretch goal — see §7.)

### Prove — CNSA 2.0 / NIST 800-131A countdown
A countdown report: "X of Y migrated, N% PQC-ready, on track for 2030" with days
remaining to each deadline, per-wave progress, and the `pqc_score_percent` trend
(reusing posture snapshots). Available as a dashboard tile and a branded PDF.

## 5. Reuse (keeps this small)

- `internal/pqc/planner.go` (classification/roadmap) — wire + enrich, don't rebuild.
- Posture snapshots (`pqc_score_percent` trend) — the proof data already accrues.
- v1.4 `fpdf` renderer + evidence-pack handler pattern — for the PQC PDF.
- v1.4 DB-store pattern (`newDBProviderState`, self-ensuring schema) — for waves.
- ML-DSA/hybrid issuance — the execute transport.

## 6. Risks

- **HNDL scoring is heuristic**: be explicit it's a risk *indicator*, not a
  guarantee; show the reason per cert. Avoid false precision.
- **Wave derivation accuracy**: auto-assignment from labels/SAN is a starting
  point; always allow manual override and log what was auto-assigned.
- **Deadline drift**: anchor dates (2030/2031) are config constants — keep them
  in one place (reuse the sunset logic) so they don't diverge across reports.
- **Determinism**: PQC PDF inherits the v1.4 caveat (fpdf random font tag) —
  assert validity/content, not byte-equality.

## 7. Decisions (locked 2026-06-17)

1. **Wave assignment: auto-derive + manual override** (W2). Default wave from
   ownership team / labels / public-vs-internal by SAN/CN; always reassignable;
   log auto-assignments.
2. **Featured deadline: show both countdowns** (CNSA 2.0 2030/2031 + NIST
   800-131A 2030), leading with the nearer one per cert class (W3).
3. **Execute: track status only** for v1.5 (pending → migrating → migrated,
   flipping on PQCReadiness change at renewal). A "migrate now" re-issue action
   is deferred to v1.5.1.
4. **PQC report: dashboard + PDF from the start** (W3) — it's the board artifact.

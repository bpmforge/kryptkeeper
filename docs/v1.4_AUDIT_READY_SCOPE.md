# Kryptkeeper v1.4 — Audit-Ready Evidence Packs (Scope)

**Date:** 2026-06-17
**Plan reference:** `docs/archive/GO_FORWARD_PLAN.md` §5 (v1.4 row)
**Status:** SHIPPED — v1.4.0 (tagged; see CHANGELOG.md). This doc is the original scoping record; per-item statuses below are historical. _(Re-statused 2026-07-15, design review G-7.)_

## 1. The thesis

> Tools that *generate the evidence* get bought; tools that show dashboards get
> evaluated. "Built for the person who has to sit in the audit."

v1.4 converts users into champions: a CISO can hand their auditor a branded PDF
that maps the framework's controls to live cert posture — no screenshotting
dashboards. This is the "my auditor loved it" release.

## 2. What already exists (code-verified 2026-06-17)

- **Evidence content**: `computeComplianceEvidence(certs, cas, framework)` →
  `ComplianceEvidenceReport{Controls[], Summary{pass,warn,fail}}` for `soc2`,
  `pci`, `nist`, `all`. Each control has id, title, status, evidence,
  remediation. **The substance of the pack already exists** — v1.4 packages it.
- **Posture/SLO metrics**: `computeCryptoPosture` (PQC score, automation %,
  grade distribution, expiry buckets, risk breakdown) and the renewal SLO — the
  inputs to an executive one-pager.
- **Email delivery**: `internal/notifications/delivery.SMTPChannel`
  (Host/Port/From) + a retrying `Worker`. Scheduled delivery has a transport.
- **Format-param pattern**: reports already branch on `?format=csv`
  (`writeCryptoPostureCSV`) — the PDF endpoint mirrors this.
- **Daily-job pattern**: `PostureScheduler` / `RenewalScheduler` are the
  template for a scheduled-delivery job.

What's missing: PDF rendering, an executive summary aggregate, scheduled
delivery wiring, and UI download/schedule controls.

## 3. Key decision — PDF library

The production binary is built `CGO_ENABLED=0`, so the PDF library **must be
pure Go**. Chosen: **`github.com/go-pdf/fpdf`** (maintained fork of
jung-kurt/gofpdf, pure Go, no browser/CGO). Rejected:
- headless-Chrome HTML→PDF (chromedp) — needs a browser in the minimal
  distroless container; heavy and fragile.
- maroto v2 — nicer API but a heavier dependency; fpdf is enough for tabular
  evidence packs and a one-pager.

API must be verified against `node_modules`-equivalent (Go: read the package /
Context7) before coding, per the pre-code rule.

## 4. Deliverables

### A. PDF rendering core (`internal/report/pdf` or `internal/bootstrap`)

- A thin branded-document helper over fpdf: header (logo/title/generated-at),
  footer (page N of M, classification line), section headings, a status-colored
  table renderer (pass=green, warn=amber, fail=red), and a summary band.
- Pure rendering — takes already-computed report structs, returns bytes. No
  data access, fully unit-testable (assert non-empty valid PDF + that key
  strings appear in the content stream).

### B. Compliance evidence pack — PDF

- `GET /api/v1/reports/compliance-evidence?framework=pci&format=pdf` (mirrors
  the CSV branch). Renders the `ComplianceEvidenceReport` as a branded pack:
  cover (framework, org, date, pass/warn/fail summary), one section per control
  with status badge + evidence + remediation, an appendix listing the certs the
  evidence draws from.
- Per-framework cover/title (PCI DSS 4.0.1, SOC 2, NIST SP 800-57).

### C. Executive one-pager — PDF

- New `computeExecutiveSummary(certs, cas)` aggregating posture score, PQC
  readiness, automation %, compliance pass-rate, expiry risk (≤47d / expired),
  and top risks — one page, branded, board-readable.
- `GET /api/v1/reports/executive-summary?format=pdf` (and `?format=json` for the
  dashboard tile).

### D. Scheduled delivery

- `EvidenceScheduler` (same shape as PostureScheduler): on a cadence, render the
  configured pack(s) and email them via `SMTPChannel` to the configured
  recipients; audit each send.
- Config: env for SMTP (`SMTP_HOST/PORT/FROM/...`) + a small persisted schedule
  (framework, cadence weekly/monthly, recipients) — migration `000016`
  `evidence_schedules`, or env-only for v1.4.0 with DB in v1.4.1. **Decision
  needed (see §7).**
- Manual trigger: `POST /api/v1/reports/evidence/send` (gated to admin) — "email
  it now," returns per-recipient result. Reuses the SIEM-test UX pattern.

### E. Dashboard

- ComplianceEvidence page: **Download PDF** per framework + **Executive
  one-pager** button (just links to the `format=pdf` URLs, like the existing
  CSV download).
- Scheduled-delivery panel (on Settings or a Reports settings area): recipients,
  cadence, framework, "Send now" + last-send status.
- Executive-summary tile on the Dashboard (from `format=json`).

## 5. Suggested waves

| Wave | Content | Notes |
|------|---------|-------|
| W1 | PDF core (A) + compliance evidence PDF (B) + UI download buttons | Self-contained, shippable as v1.4.0-beta |
| W2 | Executive one-pager (C) + dashboard tile | Composes existing computes |
| W3 | Scheduled delivery (D) + manual send + UI schedule panel | Depends on SMTP config |

Each wave is its own PR, green build + tests, mirroring the v1.3 cadence.

## 6. Risks

- **PDF determinism in tests**: fpdf embeds a creation timestamp — pass a fixed
  time in (don't call time.Now inside the renderer) so golden-ish assertions are
  stable. (Matches the existing "no time.Now in pure functions" pattern.)
- **Font/asset embedding**: fpdf core fonts (Helvetica) need no asset files —
  stick to core fonts to keep the CGO-free distroless image asset-free. A logo
  would be an embedded PNG (small, optional).
- **SMTP in prod**: needs real SMTP creds; until configured, scheduled delivery
  stays disabled (opt-in, like SIEM). Manual "Send now" returns a clear "SMTP
  not configured" 400.
- **Large fleets**: cap the per-control cert appendix (top-N + count) so a
  10k-cert pack doesn't produce a 500-page PDF; log what was truncated.

## 7. Decisions (locked 2026-06-17)

1. **Schedule storage: DB-backed** — `evidence_schedules` table (migration
   `000016`), editable in the UI. Matches the v1.2 dashboard-editable theme.
   (Delivered in W3.)
2. **Branding**: configurable **org name** now (env / setting); customer logo
   later. Core Helvetica fonts only (keeps the distroless image asset-free).
3. **Frameworks at launch: the 3 already mapped** — PCI DSS 4.0.1, SOC 2,
   NIST SP 800-57. FedRAMP/CMMC are a later mapping effort.
4. **One-pager audience: exec-first** — fewer numbers, headline metrics; the
   dense view is the existing dashboard.

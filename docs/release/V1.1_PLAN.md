# Kryptkeeper 1.1 plan

the owner picked all three scope options (A easy to adopt, B fits your tools, C ahead of the standards) on
2026-10-25 and named **CA choice** the main thing. The review behind the pick is in the project
library (`KRYPTKEEPER_1.1_PROPOSAL.md`). The waves below run in this order. Each wave gets its own design doc
(`docs/board/specs/W3x-00-DESIGN.md`), tickets file and branch, and updates `docs/ROADMAP.md`
in the same PR.

| Wave | Theme | Scope | ROADMAP refs |
|---|---|---|---|
| **W36** | CA choice | External CAs behind every front door (D-304); upstream-first revoke (D-306); Vault PKI, EJBCA, AWS Private CA, Google CAS, Sectigo, GlobalSign, Entrust connectors plus DigiCert and ACME revoke; Issuers page and wizard with ACME presets; live Vault and EJBCA proof | new rows, W36-* |
| **W37** | Easy to adopt | Helm chart repository and images on every release; Homebrew tap; signed apt and yum repositories; macOS notarization; Terraform registry; Ansible collection; five-minute trial (compose and `helm install` with demo data) on kryptkeeper.io; reproducible-build check; release workflows on git.example.test | D-210, W25-10, W25-11, W33-09, S-04 |
| **W38** | Fits your tools | PAM credential source (CyberArk, Delinea, Vault, OpenBao) for SSH and WinRM targets; Teams alerts, owner-team routing with an ownerless queue, retries with backoff; ITSM ticket on a failed manual renewal; cloud certificates as inventory rows and per-agent inventory API; Intune SCEP challenge validation; scheduled CSV, XLSX and PDF reports and the key-readiness line | W32-29..32, W24-45, W24-46, W20-23, W28-06, W24-49 |
| **W39** | Windows and rate safety | SQL Server, Exchange and RDP install modes and the RDP NLA read; port-80 preflight; persisted rate-limit backoff and a rolling issuance budget per CA; older Windows autoenrollment proofs | W35-01..04, W24-48, W24-50, W27-39, W26-13/14 |
| **W40** | Ahead of the standards | PQC delivery to IIS, Kubernetes, HAProxy and Tomcat; ACME device attestation (TPM, Apple); trust store push to agents; more DNS-01 providers; PQC posture proof on more certificate types | D-300, W31F-07 |
| **Quality (every wave)** | | Refresh token in an httpOnly cookie, tenant name in logs, base images pinned by digest, screen-reader pass | V1 scan, W33-15 |

Partner proofs (cloud DNS and KMS, Slack, PagerDuty, Jira Cloud, ServiceNow, DigiCert, Sectigo,
GlobalSign, Entrust, F5, Citrix, HSM) need accounts the owner chooses to fund. They stay `Needs partner hardware`
until then.

Release: 1.1.0 is tagged once all five waves are merged, CI shows an explicit success and the owner types go.
